# 選考路線図 — 就活の選考管理ツール

インターンと本選考のエントリーを記録し、**「インターンに何社参加したか」「本選考は何社中いま何社が進行中か」**を画面上部で一目で確認できる、ブラウザだけで動く就活管理ツールです。

同じ企業でも夏インターン・春インターン・本選考・職種違いは**別のエントリー**として記録し、一覧では**企業名ごとに1枚のカード**へ自動でまとまります。

PCとスマホで**同じデータ**を見られます（下記「端末間の同期」を設定した場合）。

---

## 主な機能

| 機能 | 内容 |
|---|---|
| 集計バー | インターン参加社数 / 本選考の「◯社中◯社が選考中」/ 内定社数 / ES提出済み件数を常時表示 |
| 企業ごとの集約 | 同じ企業名のエントリーは1つのカードにまとまる。夏・春・本選考を並べて比較できる |
| 選考路線図 | 選考の各段階を駅に見立てて表示。駅を押すだけで現在地を変更できる |
| ステップの自由編集 | 選考の流れは企業ごとに違うため、ステップの追加・削除・名称変更が可能 |
| 締切の信号表示 | 期限までの日数を停止（赤）/ 注意（橙）/ 進行（緑）で色分けし、7日以内のものを上部にまとめる |
| 端末間の同期 | GitHub のプライベートリポジトリを保管場所にして、PCとスマホで同じデータを読み書き |
| 記録 | 段階の変更や結果の確定を日付つきで自動記録 |
| 書き出し / 読み込み | データをテキストとして控えられる |

## セットアップ

### 1. アプリを公開する（パブリックリポジトリ）

1. このフォルダの中身をリポジトリのルートに置いて push する
2. **Settings → Pages** を開く
3. **Source** で `Deploy from a branch`、ブランチ `main`、フォルダ `/ (root)` を選んで保存
4. 数分後に `https://<ユーザー名>.github.io/<リポジトリ名>/` で開ける

このリポジトリには**コードしか入りません**。選考データは一切含まれないので、パブリックで問題ありません。

スマホでこのURLを開き、ホーム画面に追加しておくとアプリのように使えます。

### 2. データ置き場を作る（プライベートリポジトリ）

1. 新しいリポジトリを作る（例：`shukatsu-data`）
2. **Private** を選ぶ
3. **Add a README file** にチェックを入れて作成する（空のままだと同期が始められません）

### 3. アクセストークンを発行する

1. GitHub 右上のアイコン → **Settings**
2. 左メニュー最下部の **Developer settings**
3. **Personal access tokens → Fine-grained tokens** → **Generate new token**
4. 次のように設定する
   - **Token name**：`shukatsu`（何でも可）
   - **Expiration**：就活が終わる頃までの日付
   - **Repository access**：`Only select repositories` → 手順2で作った `shukatsu-data` を選ぶ
   - **Permissions → Repository permissions → Contents**：`Read and write`
5. **Generate token** を押し、表示されたトークンをコピーする（**この画面を離れると二度と表示されません**）

権限をこのリポジトリ1つ・Contents だけに絞っているので、万一漏れても影響はこのデータに限られます。

### 4. アプリに登録する

1. アプリを開き、画面下の **「端末間の同期を設定」** を押す
2. GitHubユーザー名 / リポジトリ名（`shukatsu-data`）/ トークンを入力
3. **「接続して同期する」** を押す
4. スマホでも同じ手順を行う（トークンは同じものを使い回して構いません）

ツールバーの丸印が緑になれば同期できています。押すといつでも手動で同期できます。

## 同期の仕組みと注意点

- データは `data.json` という1ファイルとして、プライベートリポジトリに保存されます。
- 編集すると約1.5秒後に自動で送信されます。アプリを開いたときと、画面に戻ってきたときにも読み直します。
- **PCとスマホの両方で編集しても消えません。** エントリーごとに更新時刻を持たせ、新しい方を採用します。削除も記録されるため、古い端末のデータから復活することはありません。
- トークンは各端末のブラウザ内にだけ保存され、リポジトリには入りません。
- **トークンの有効期限が切れると同期エラーになります。** 新しく発行して各端末で貼り直してください。
- 端末を紛失した場合は、GitHub の Fine-grained tokens 画面からそのトークンを Revoke してください。
- **マイページのパスワードは保存しないでください。** データは暗号化されていません。

同期を設定しない場合も、これまで通り各端末のブラウザ内だけで動きます。

## ファイル構成

```
.
├── index.html          画面の骨組み
├── css/
│   └── styles.css      配色・書体・レイアウト
├── js/
│   ├── storage.js      端末内の保存
│   ├── model.js        データ定義・集計・端末間マージ
│   ├── view.js         描画処理
│   ├── editor.js       追加・編集・同期設定のモーダル
│   ├── sync.js         GitHub との読み書き
│   └── main.js         イベント登録と初期化
├── README.md
└── .gitignore
```

`js/` は ES Modules ではなく通常の `<script>` として順に読み込んでいます。`file://` で直接開いてもそのまま動かすためです。読み込み順を変えるときは `index.html` 末尾の並びに注意してください。

## カスタマイズ

選考ステップの初期値は `js/model.js` の冒頭にあります。受ける業界に合わせて書き換えられます。

```js
var TEMPLATES = {
  intern: ['エントリー', 'ES提出', '適性検査', '面接', '参加確定', '参加済み'],
  honsen: ['プレエントリー', 'ES提出', '適性検査', '一次面接', '二次面接', '最終面接', '内定']
};
```

配色や書体は `css/styles.css` 冒頭の `:root` にまとめてあります。インターンは藍色、本選考は臙脂色、締切の緊急度は鉄道信号の3色に対応しています。
